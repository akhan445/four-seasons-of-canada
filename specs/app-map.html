Four Seasons of Canada: App Map

A take-home guide to how the app is built. It is a snapshot of source commit 60e190d and can drift as the code changes.

What the app is

One web page that runs entirely in the browser (no server, no saved data). Choosing a season changes the whole page's look, and a bulletin-board map of Canada shows thumbtacks for things unique to that season. Hovering or clicking a tack opens a card.

  • State lives in App (the current season, whether the intro is open, which tack is hovered or locked, which item the card shows).
  • Components draw the screen from that state: season buttons, intro pop-up, map board, tacks, tack card, and the season decorations.
  • One data file holds all the content; CSS does the looks and motion.

One action, followed through

Click a tack, move the mouse away, then click outside the card.

A route through the code (reference, not toured)

1. The click: src/components/Tack.tsx

Search for onClick={() => onClick(tack.id)}. The tack does not know about cards; it only reports which tack was clicked.

2. The memory: src/App.tsx

Search for clickTack, which calls setLockedTackId(id), and closeCard, which sets it back to null. This one piece of state is why the card stays open after the mouse leaves.

3. The listener: src/hooks/useClickOutside.ts

The useEffect adds a mousedown listener to the whole page, and the function it returns removes it. Without that cleanup, old listeners would pile up each time a card opens. TackCard.tsx calls this hook with useClickOutside(cardRef, onClose, locked).

A practice to reuse

Write the expected behavior as something you can observe, then verify it by actually running it.

  • Decision: specs/prd.md states each behavior as a checkable result, such as "Clicking outside closes the card."
  • Evidence: when the map board was added, running the page and trying to close the intro pop-up showed the board was covering it. That bug is recorded in specs/checklist.md under Revisions, and a one-line stacking fix resolved it. Reading the code alone had not shown it.
  • Reuse: on any project, turn each requirement into "when I do X, I should see Y," and run exactly that before moving on.
